    Developer Guide¶

    이 가이드는 개발자가 Prism SDK와 Spring Boot Starter를 사용하여 A/B 테스트를 구현하는 상세한 방법을 설명합니다.

    핵심 개념¶

    1. 실험 (Experiment)¶

    사용자를 특정 그룹(Variant)에 할당하는 과정입니다. - Control (대조군): 기본 로직이 적용되는 그룹 - Treatment (실험군): 새로운 기능이나 변경 사항이 적용되는 그룹

    2. 전환 (Conversion)¶

    실험의 목표가 되는 사용자 행동입니다. (예: 구매, 클릭, 회원가입)

    3. 퍼널 (Funnel)¶

    여러 단계의 전환을 연결한 사용자 여정입니다.

    상품 조회 → 장바구니 담기 → 결제 완료
  (실험)      (전환 1)        (전환 2)

    구현 가이드¶

    1. 실험 참가 (Assignment)¶

    @PrismExperiment 어노테이션을 사용하여 실험을 선언합니다.

    @GetMapping("/api/shop/products/{id}")
@PrismExperiment(experimentKey = "checkout-flow")
fun getProduct(
    @PathVariable id: Long,
    @PrismUserId @RequestParam userId: String
): ProductDto {
    // PrismContext를 통해 할당된 Variant 접근
    val variant = PrismContext.getCurrentVariant()

    // Variant에 따른 로직 분기
    return when (variant) {
        "multi_step" -> productDto.copy(checkoutType = "MULTI")
        "one_page" -> productDto.copy(checkoutType = "ONE")
        else -> productDto // 기본값 (Control)
    }
}

    핵심 어노테이션: - @PrismUserId: 사용자 식별자를 파라미터에서 자동으로 추출합니다. - PrismContext.getCurrentVariant(): 현재 요청 컨텍스트에 할당된 변형 값을 반환합니다.

    2. 전환 추적 (Conversion Tracking)¶

    전환 추적에는 두 가지 방법이 있습니다.

    방법 1: @PrismTrackConversion 어노테이션 (선언적)¶

    메서드 실행 완료 후 자동으로 전환 이벤트를 추적합니다.

    @PostMapping("/api/checkout")
@PrismTrackConversion(
    experimentKey = "checkout-flow",
    eventName = "purchase"
)
fun checkout(@RequestBody request: CheckoutRequest) {
    // 주문 로직 수행
    orderService.process(request)

    // 메서드가 성공적으로 종료되면 자동으로 'purchase' 이벤트가 전송됩니다.
}

    어노테이션 속성:

    속성 타입 필수 기본값 설명
    experimentKey String ✅ - 실험 키
    eventName String ✅ - 이벤트 이름
    userIdParam String ❌ "userId" userId 파라미터 이름
    trackOnException Boolean ❌ false 예외 발생 시에도 추적 여부
    trackWhen TrackCondition ❌ ALWAYS 추적 조건

    방법 2: PrismConversionTracker 서비스 (프로그래매틱)¶

    조건부 추적이나 복잡한 로직이 필요한 경우 사용합니다.

    @Service
class CheckoutService(
    private val conversionTracker: PrismConversionTracker
) {
    @PrismExperiment(experimentKey = "checkout-flow")
    fun completePurchase(
        @PrismUserId userId: String,
        amount: Int
    ) {
        // 구매 로직...

        // 조건부 전환 추적
        if (amount > 0) {
            conversionTracker.trackConversionSafe(
                userId = userId,
                experimentKey = "checkout-flow",
                eventName = "purchase"
            )
        }
    }
}

    3. 다중 이벤트 추적¶

    하나의 메서드에서 여러 전환 이벤트를 동시에 추적할 수 있습니다.

    // 여러 이벤트 동시 추적 (@Repeatable)
@PrismTrackConversion(experimentKey = "signup", eventName = "page_viewed")
@PrismTrackConversion(experimentKey = "signup", eventName = "form_started")
fun showSignupForm(@PrismUserId userId: String) {
    // page_viewed와 form_started 두 이벤트 모두 기록됨
}

// 조건부 다중 이벤트
@PrismTrackConversion(experimentKey = "signup", eventName = "submitted")
@PrismTrackConversion(
    experimentKey = "signup",
    eventName = "success",
    trackWhen = TrackCondition.RETURN_TRUE
)
fun submitSignup(@PrismUserId userId: String): Boolean {
    // submitted는 항상 기록
    // success는 true 반환 시에만 기록
    return registerUser()
}

    4. 다단계 퍼널 (Funnel) 설계¶

    여러 단계의 전환을 추적하여 퍼널을 구성할 수 있습니다.

    예시: E-commerce 구매 여정¶

    @RestController
@RequestMapping("/shop")
class ShopFunnelController(
    private val conversionTracker: PrismConversionTracker
) {
    // Step 1: 상품 조회 (실험 참가)
    @GetMapping("/products/{id}")
    @PrismExperiment(experimentKey = "buy_button_color")
    fun viewProduct(
        @PathVariable id: Long,
        @PrismUserId @RequestParam userId: String
    ): ProductResponse {
        val variant = PrismContext.getCurrentVariant() ?: "CONTROL"
        return productService.getProduct(id, variant)
    }

    // Step 2: 장바구니 담기 (중간 전환)
    @PostMapping("/cart/add")
    @PrismExperiment(experimentKey = "buy_button_color")
    fun addToCart(
        @PrismUserId @RequestParam userId: String,
        @RequestParam productId: Long
    ): CartResponse {
        val result = cartService.addItem(userId, productId)

        conversionTracker.trackConversionSafe(
            userId = userId,
            experimentKey = "buy_button_color",
            eventName = "ADD_TO_CART"
        )

        return result
    }

    // Step 3: 결제 완료 (최종 전환)
    @PostMapping("/checkout")
    @PrismExperiment(experimentKey = "buy_button_color")
    fun checkout(
        @PrismUserId @RequestParam userId: String,
        @RequestBody request: CheckoutRequest
    ): CheckoutResponse {
        val result = orderService.process(request)

        conversionTracker.trackConversionSafe(
            userId = userId,
            experimentKey = "buy_button_color",
            eventName = "PURCHASE"
        )

        return result
    }
}

    퍼널 분석 결과 예시: 

    상품 조회 (Impression): 1,000명
    ↓ (전환율 30%)
장바구니 담기: 300명
    ↓ (전환율 50%)
결제 완료: 150명

전체 전환율: 15%

    5. 순수 퍼널 추적 (@PrismFunnelEvent)¶

    A/B 테스트와 독립적으로 사용자의 행동 흐름을 추적할 때는 @PrismFunnelEvent를 사용합니다.

    특징¶

    구분 @PrismTrackConversion @PrismFunnelEvent
    용도 A/B 테스트 전환 추적 순수 퍼널 분석
    experimentKey 필요 ✅ 필수 ❌ 불필요
    실험 등록 필요 ✅ 필수 ❌ 불필요
    데이터 저장 conversion_log 테이블 funnel_event 테이블
    사용 시점 A/B 테스트 성과 측정 사용자 여정 분석

    기본 사용법¶

    @RestController
@RequestMapping("/examples/shop")
class ShopFunnelController {

    // 장바구니 담기 (자동 추적)
    @PostMapping("/cart/add")
    @PrismFunnelEvent(
        eventName = "ADD_TO_CART",
        funnelKey = "purchase_flow"
    )
    fun addToCart(
        @PrismUserId @RequestParam userId: String,
        @RequestParam productId: Long,
        @RequestParam(defaultValue = "1") quantity: Int
    ): CartResponse {
        // 메서드 실행 후 자동으로 funnel_event 테이블에 이벤트 기록
        return cartService.addItem(userId, productId, quantity)
    }

    // 결제 완료
    @PostMapping("/checkout")
    @PrismFunnelEvent(
        eventName = "PURCHASE",
        funnelKey = "purchase_flow"
    )
    fun checkout(
        @PrismUserId @RequestParam userId: String,
        @RequestBody request: CheckoutRequest
    ): CheckoutResponse {
        val total = cartService.calculateTotal(request.cartItems)
        return CheckoutResponse(
            message = "Purchase completed",
            userId = userId,
            value = total
        )
    }

    // 주문 완료 확인
    @PostMapping("/order/complete")
    @PrismFunnelEvent(
        eventName = "ORDER_COMPLETE",
        funnelKey = "purchase_flow"
    )
    fun completeOrder(
        @PrismUserId @RequestParam userId: String,
        @RequestParam orderId: String
    ): String {
        return "Order $orderId completed for user $userId"
    }
}

    어노테이션 속성¶

    속성 타입 필수 기본값 설명
    eventName String ✅ - 퍼널 이벤트 이름
    funnelKey String ❌ "" 퍼널 그룹 키 (선택)
    userIdParam String ❌ "userId" userId 파라미터 이름
    trackOnException Boolean ❌ false 예외 발생 시에도 추적 여부

    여러 이벤트 동시 추적¶

    @PrismFunnelEvent는 반복 가능(Repeatable)하므로 하나의 메서드에 여러 번 사용할 수 있습니다.

    // 페이지 진입과 동시에 두 이벤트 기록
@PrismFunnelEvent(eventName = "page_viewed")
@PrismFunnelEvent(eventName = "interaction_started", funnelKey = "engagement")
fun showPage(@PrismUserId userId: String) {
    // page_viewed와 interaction_started 두 이벤트 모두 기록됨
}

    세션 지원¶

    비로그인 사용자나 세션 기반 추적이 필요한 경우 @PrismSessionId를 함께 사용합니다.

    @PostMapping("/cart/add")
@PrismFunnelEvent(
    eventName = "add_to_cart",
    funnelKey = "purchase_flow"
)
fun addToCart(
    @PrismUserId userId: String,
    @PrismSessionId sessionId: String,  // 세션 ID도 함께 기록
    @RequestParam productId: Long
) {
    // ...
}

    Admin에서 퍼널 정의 및 분석¶

    1. 퍼널 정의: Admin > Analytics > Funnel Management > Create Funnel
    2. Name: 쇼핑 구매 여정
    3. Data Source: Funnel Event 선택

    4. Steps: ADD_TO_CART, PURCHASE, ORDER_COMPLETE (순서대로)

    5. 분석 결과: Analytics > Funnel Analysis

    6. 단계별 전환율 및 이탈율 시각화
    7. 날짜 범위 필터 (7일, 14일, 30일, 90일)

    장점¶

    • ✅ 실험 등록 불필요: Admin에서 실험을 만들지 않아도 즉시 사용 가능
    • ✅ 코드 간결: 이전 방식 대비 5줄 → 1줄로 단순화
    • ✅ 독립적 추적: A/B 테스트와 무관하게 순수 사용자 행동 분석
    • ✅ 비동기 저장: Kotlin Coroutines를 사용하여 메인 로직에 영향 없음

    필수 조건¶

    FunnelEventRepository Bean이 필요합니다. prism-infrastructure:persistence-jpa 모듈을 의존성에 추가하세요.

    dependencies {
    implementation("io.github.silbaram.prism:prism-infrastructure-persistence-jpa")
}

    통계 오염 방지 (중요)¶

    왜 trackConversionSafe()를 사용해야 하는가?¶

    API 장애 시 통계 왜곡을 방지합니다.

    API 정상 시:
  - impression: variant=A 기록됨 ✅
  - conversion: variant=A 기록됨 ✅
  - 통계 정확 ✅

API 장애 시 (trackConversionSafe 사용):
  - impression: 기록 안 됨 (API 실패)
  - conversion: 기록 안 됨 (자동 스킵) ✅
  - 통계 정확 유지 ✅

API 장애 시 (직접 호출 - 금지):
  - impression: 기록 안 됨
  - conversion: 기록됨 ❌
  - 통계 오염! (impression 0인데 conversion만 증가) ❌

    금지 패턴¶

    // ❌ 절대 금지! 통계 오염 위험
prismClient.trackConversion(userId, experimentKey, eventName)

    권장 패턴¶

    // ✅ 안전한 래퍼 사용
conversionTracker.trackConversionSafe(userId, experimentKey, eventName)

// ✅ 어노테이션 사용
@PrismTrackConversion(experimentKey = "...", eventName = "...")

    PrismContext API¶

    현재 요청 컨텍스트에서 실험 정보를 조회합니다.

    // 할당된 변형 조회
val variant: String? = PrismContext.getCurrentVariant()

// 실제 할당 여부 확인 (API 장애 시 false)
val wasAssigned: Boolean = PrismContext.wasActuallyAssigned()

    사용 예시:

    @GetMapping("/products/{id}")
@PrismExperiment(experimentKey = "product_layout")
fun getProduct(
    @PathVariable id: Long,
    @PrismUserId @RequestParam userId: String
): ProductResponse {
    val variant = PrismContext.getCurrentVariant()
    val wasAssigned = PrismContext.wasActuallyAssigned()

    return when {
        !wasAssigned -> {
            // API 장애 - 기본 레이아웃 반환
            productService.getProductDefault(id)
        }
        variant == "grid" -> productService.getProductGrid(id)
        variant == "list" -> productService.getProductList(id)
        else -> productService.getProductDefault(id)
    }
}

    설정 (Configuration)¶

    application.yml에서 Prism 설정을 관리할 수 있습니다.

    prism:
  api:
    url: "http://localhost:8080"   # Prism API 서버 주소
    timeout: 3000                  # 타임아웃 (ms)
  fallback:
    enabled: true                  # API 장애 시 기본값 사용 여부

    예외 처리¶

    Prism SDK는 Fail-Safe를 지향합니다.

    • API 서버 연결 실패 시 기본값(Control)을 반환합니다.
    • 실험 할당 로직에서 에러가 발생해도 메인 비즈니스 로직에는 영향을 주지 않습니다.
    @GetMapping("/products/{id}")
@PrismExperiment(experimentKey = "product_layout")
fun getProduct(id: Long, @PrismUserId userId: String): ProductResponse {
    // API 장애 시에도 이 메서드는 정상 실행됨
    // PrismContext.getCurrentVariant()는 null 또는 기본값 반환
    val variant = PrismContext.getCurrentVariant() ?: "CONTROL"
    return productService.getProduct(id, variant)
}

    모범 사례¶

    1. 실험 키 명명 규칙¶

    // ✅ 좋음: 명확하고 일관된 명명
"buy_button_color"
"checkout_flow_v2"
"homepage_banner_position"

// ❌ 나쁨: 모호하거나 불일치
"test1"
"exp"
"buttonColor"  // snake_case 권장

    2. 이벤트 이름 명명 규칙¶

    // ✅ 좋음: 동작을 명확히 표현
"ADD_TO_CART"
"PURCHASE"
"SIGNUP_COMPLETE"

// ❌ 나쁨: 모호함
"click"
"done"
"event1"

    3. userId 일관성 유지¶

    동일한 사용자에게 일관된 경험을 제공하려면 userId를 일관되게 사용하세요.

    // ✅ 좋음: 세션 전체에서 동일한 userId 사용
@GetMapping("/products/{id}")
fun getProduct(@PrismUserId @RequestParam userId: String) // user123

@PostMapping("/cart/add")
fun addToCart(@PrismUserId @RequestParam userId: String)  // user123 (동일)

// ❌ 나쁨: userId가 달라지면 다른 그룹에 할당될 수 있음
@GetMapping("/products/{id}")
fun getProduct(@RequestParam sessionId: String)  // session-abc

@PostMapping("/cart/add")
fun addToCart(@RequestParam visitorId: String)   // visitor-xyz (다름!)
