    API 레퍼런스¶

    Prism A/B 테스트 플랫폼의 완전한 API 레퍼런스입니다.

    개요¶

    Prism은 세 가지 유형의 API를 제공합니다:

    유형 Base URL 설명
    Core API http://localhost:8080 트래픽 분배, 전환 추적, 분석
    Admin API http://localhost:8070 실험 관리, 통계 조회
    Examples API http://localhost:8090 E-commerce 퍼널 예제

    Core API 엔드포인트 요약¶

    메서드 경로 설명
    GET /v1/assign 사용자를 실험 그룹에 할당
    POST /v1/conversions 전환 이벤트 추적
    GET /v1/analytics/funnel 퍼널 분석 (단계별 전환율)
    GET /v1/analytics/journeys 사용자 여정 분석 (경로 패턴)

    Core API¶

    1. 트래픽 분배 (Variant Assignment)¶

    사용자를 A/B 테스트 변형(Variant)에 할당합니다.

    GET /v1/assign¶

    파라미터:

    이름 타입 필수 설명
    userId string ✅ 사용자 고유 식별자
    experimentKey string ✅ 실험 키

    요청 예시: 

    curl "http://localhost:8080/v1/assign?userId=user123&experimentKey=buy_button_color"

    응답 (200 OK): 

    {
  "userId": "user123",
  "experimentKey": "buy_button_color",
  "variant": "red_button",
  "resultCode": "SUCCESS",
  "resultMessage": "성공"
}

    응답 필드:

    필드 타입 설명
    userId string 요청한 사용자 ID
    experimentKey string 요청한 실험 키
    variant string | null 할당된 변형 이름 (실패 시 null)
    resultCode string 결과 코드 (SUCCESS, EXPERIMENT_NOT_FOUND 등)
    resultMessage string 결과 메시지

    코드 예제 (Kotlin): 

    // SDK 사용
val result = prismClient.assign("user123", "buy_button_color")
println("할당된 변형: ${result.variant}")

// HTTP 직접 호출
val response = restTemplate.getForObject(
    "http://localhost:8080/v1/assign?userId={userId}&experimentKey={key}",
    AssignmentResponse::class.java,
    "user123", "buy_button_color"
)

    2. 전환 추적 (Conversion Tracking)¶

    사용자의 전환 이벤트(구매, 클릭 등)를 추적합니다.

    POST /v1/conversions¶

    요청 본문: 

    {
  "userId": "user123",
  "experimentKey": "buy_button_color",
  "eventName": "purchase",
  "sessionId": "session-abc-123"
}

    필드 타입 필수 설명
    userId string ✅ 사용자 고유 식별자
    experimentKey string ✅ 실험 키
    eventName string ✅ 이벤트 이름 (예: purchase, add_to_cart)
    sessionId string ❌ 세션 ID (미제공 시 자동 생성, 쿠키로 관리)

    요청 예시: 

    curl -X POST "http://localhost:8080/v1/conversions" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "user123",
    "experimentKey": "buy_button_color",
    "eventName": "purchase"
  }'

    응답 (200 OK): 

    {
  "userId": "user123",
  "experimentKey": "buy_button_color",
  "eventName": "purchase",
  "variant": "red_button",
  "resultCode": "SUCCESS",
  "resultMessage": "전환이 성공적으로 기록되었습니다."
}

    세션 관리: - sessionId를 제공하지 않으면 서버가 자동 생성합니다. - 응답 헤더의 Set-Cookie: PRISM_SESSION_ID=...로 세션 쿠키가 설정됩니다. - 세션 유효 기간: 30분

    코드 예제 (Kotlin): 

    // SDK 사용 (권장)
prismClient.trackConversion("user123", "buy_button_color", "purchase")

// HTTP 직접 호출
val request = ConversionRequest(
    userId = "user123",
    experimentKey = "buy_button_color",
    eventName = "purchase"
)
restTemplate.postForObject(
    "http://localhost:8080/v1/conversions",
    request,
    ConversionResponse::class.java
)

    3. 퍼널 분석 (Funnel Analysis)¶

    전환 퍼널의 단계별 전환율을 분석합니다.

    GET /v1/analytics/funnel¶

    파라미터:

    이름 타입 필수 기본값 설명
    experimentKey string ✅ - 실험 키
    steps string ✅ - 전환 단계 (쉼표 구분, 예: VIEW,ADD_TO_CART,PURCHASE)
    days long ❌ 7 분석 기간 (일)
    variant string ❌ null 특정 변형만 분석 (미지정 시 전체)

    요청 예시: 

    curl "http://localhost:8080/v1/analytics/funnel?experimentKey=buy_button_color&steps=VIEW,ADD_TO_CART,PURCHASE&days=7"

    응답 (200 OK): 

    {
  "experimentKey": "buy_button_color",
  "steps": ["VIEW", "ADD_TO_CART", "PURCHASE"],
  "funnelData": [
    {
      "step": "VIEW",
      "count": 1000,
      "conversionRate": 100.0
    },
    {
      "step": "ADD_TO_CART",
      "count": 350,
      "conversionRate": 35.0
    },
    {
      "step": "PURCHASE",
      "count": 120,
      "conversionRate": 34.3
    }
  ],
  "overallConversionRate": 12.0
}

    코드 예제 (Kotlin): 

    // HTTP 호출
val response = restTemplate.getForObject(
    "http://localhost:8080/v1/analytics/funnel?experimentKey={key}&steps={steps}&days={days}",
    FunnelAnalysisResponse::class.java,
    "buy_button_color", "VIEW,ADD_TO_CART,PURCHASE", 7
)

println("전체 전환율: ${response.overallConversionRate}%")
response.funnelData.forEach { step ->
    println("${step.step}: ${step.count}명 (${step.conversionRate}%)")
}

    4. 사용자 여정 분석 (Journey Analysis)¶

    사용자들의 이벤트 경로 패턴을 분석합니다.

    GET /v1/analytics/journeys¶

    파라미터:

    이름 타입 필수 기본값 설명
    experimentKey string ✅ - 실험 키
    days long ❌ 7 분석 기간 (일)
    variant string ❌ null 특정 변형만 분석
    limit int ❌ 200 분석할 최대 사용자 수
    topN int ❌ 10 상위 N개 경로만 반환

    요청 예시: 

    curl "http://localhost:8080/v1/analytics/journeys?experimentKey=buy_button_color&days=7&topN=5"

    응답 (200 OK): 

    {
  "experimentKey": "buy_button_color",
  "totalUsers": 150,
  "journeys": [
    {
      "path": ["VIEW", "ADD_TO_CART", "PURCHASE"],
      "count": 45,
      "percentage": 30.0
    },
    {
      "path": ["VIEW", "ADD_TO_CART"],
      "count": 38,
      "percentage": 25.3
    },
    {
      "path": ["VIEW"],
      "count": 32,
      "percentage": 21.3
    }
  ]
}

    코드 예제 (Kotlin): 

    val response = restTemplate.getForObject(
    "http://localhost:8080/v1/analytics/journeys?experimentKey={key}&topN={topN}",
    JourneyAnalysisResponse::class.java,
    "buy_button_color", 5
)

println("분석된 사용자 수: ${response.totalUsers}")
response.journeys.forEach { journey ->
    println("${journey.path.joinToString(" → ")}: ${journey.count}명 (${journey.percentage}%)")
}

    Admin API¶

    Admin 서비스에서 제공하는 관리 및 분석용 API입니다. (http://localhost:8070)

    1. 퍼널 분석 (Funnel Analysis)¶

    특정 실험의 퍼널 데이터를 조회합니다.

    GET /admin/api/analytics/funnel¶

    파라미터:

    이름 타입 필수 기본값 설명
    experimentKey string ✅ - 실험 키
    steps string ✅ - 전환 단계 (쉼표 구분)
    days long ❌ 7 분석 기간 (일)
    variant string ❌ null 특정 변형만 분석

    응답 (200 OK): FunnelAnalysisResponse (Core API와 동일 구조)

    2. 사용자 여정 분석 (Journey Analysis)¶

    GET /admin/api/analytics/journeys¶

    파라미터:

    이름 타입 필수 기본값 설명
    experimentKey string ✅ - 실험 키
    days long ❌ 7 분석 기간 (일)
    variant string ❌ null 특정 변형만 분석
    limit int ❌ 200 분석할 최대 세션 수

    응답 (200 OK): JourneyAnalysisResponse (Core API와 동일 구조)

    Spring Boot Starter API¶

    prism-spring-boot-starter를 사용하면 어노테이션 기반으로 A/B 테스트를 적용할 수 있습니다.

    어노테이션¶

    @PrismExperiment¶

    메서드 실행 전 자동으로 사용자를 실험 그룹에 할당합니다.

    @GetMapping("/products/{id}")
@PrismExperiment(experimentKey = "buy_button_color")
fun getProduct(
    @PathVariable id: Long,
    @PrismUserId @RequestParam userId: String
): ProductResponse {
    val variant = PrismContext.getCurrentVariant() ?: "CONTROL"
    return ProductResponse(id = id, buttonColor = variant)
}
    속성 타입 필수 설명
    experimentKey String ✅ 실험 키

    @PrismTrackConversion¶

    메서드 실행 완료 후 자동으로 전환 이벤트를 추적합니다.

    @PostMapping("/checkout")
@PrismTrackConversion(
    experimentKey = "buy_button_color",
    eventName = "purchase"
)
fun checkout(
    @PrismUserId @RequestParam userId: String,
    @RequestBody request: CheckoutRequest
): CheckoutResponse {
    // 결제 로직...
    return CheckoutResponse(success = true)
}
    속성 타입 필수 기본값 설명
    experimentKey String ✅ - 실험 키
    eventName String ✅ - 이벤트 이름
    userIdParam String ❌ "userId" userId 파라미터 이름
    trackOnException Boolean ❌ false 예외 발생 시에도 추적 여부
    trackWhen TrackCondition ❌ ALWAYS 추적 조건

    다중 이벤트 추적: 

    // 여러 이벤트 동시 추적 (Repeatable)
@PrismTrackConversion(experimentKey = "signup", eventName = "page_viewed")
@PrismTrackConversion(experimentKey = "signup", eventName = "form_started")
fun showSignupForm(@PrismUserId userId: String) {
    // page_viewed, form_started 두 이벤트 모두 기록됨
}

    @PrismUserId¶

    메서드 파라미터에서 사용자 ID를 자동으로 추출합니다.

    fun getProduct(
    @PrismUserId @RequestParam userId: String  // userId로 실험 할당
): ProductResponse

    @PrismFunnelEvent¶

    A/B 테스트와 독립적으로 순수 퍼널 이벤트를 추적합니다.

    @PostMapping("/cart/add")
@PrismFunnelEvent(
    eventName = "ADD_TO_CART",
    funnelKey = "purchase_flow"
)
fun addToCart(
    @PrismUserId @RequestParam userId: String,
    @RequestParam productId: Long
): CartResponse {
    // 메서드 실행 후 자동으로 funnel_event 테이블에 이벤트 기록
    return cartService.addItem(userId, productId)
}
    속성 타입 필수 기본값 설명
    eventName String ✅ - 퍼널 이벤트 이름
    funnelKey String ❌ "" 퍼널 그룹 키 (선택)
    userIdParam String ❌ "userId" userId 파라미터 이름
    trackOnException Boolean ❌ false 예외 발생 시에도 추적 여부

    특징: - ✅ experimentKey 불필요 (A/B 테스트와 독립적) - ✅ 실험 등록 불필요 (즉시 사용 가능) - ✅ 반복 가능 (Repeatable) - 하나의 메서드에 여러 이벤트 추적 가능 - ✅ funnel_event 테이블에 저장 (conversion_log와 분리)

    여러 이벤트 동시 추적: 

    @PrismFunnelEvent(eventName = "page_viewed")
@PrismFunnelEvent(eventName = "interaction_started", funnelKey = "engagement")
fun showPage(@PrismUserId userId: String) {
    // 두 이벤트 모두 자동 기록
}

    @PrismSessionId¶

    메서드 파라미터에서 세션 ID를 자동으로 추출합니다.

    @PostMapping("/cart/add")
@PrismFunnelEvent(eventName = "add_to_cart")
fun addToCart(
    @PrismUserId userId: String,
    @PrismSessionId sessionId: String  // 세션 ID도 함께 기록
): CartResponse

    서비스 클래스¶

    PrismConversionTracker¶

    안전한 전환 추적을 위한 래퍼 컴포넌트입니다. 통계 오염을 방지합니다.

    @Service
class CheckoutService(
    private val conversionTracker: PrismConversionTracker
) {
    @PrismExperiment(experimentKey = "checkout-flow")
    fun completePurchase(@PrismUserId userId: String, amount: Int) {
        // 구매 로직...

        // 안전한 전환 추적 (할당 실패 시 자동 스킵)
        conversionTracker.trackConversionSafe(
            userId = userId,
            experimentKey = "checkout-flow",
            eventName = "purchase"
        )
    }
}

    왜 필요한가? 

    API 정상 시:
  - impression: variant=A 기록됨 ✅
  - conversion: variant=A 기록됨 ✅
  - 통계 정확 ✅

API 장애 시 (trackConversionSafe 사용):
  - impression: 기록 안 됨 (API 실패)
  - conversion: 기록 안 됨 (자동 스킵) ✅
  - 통계 정확 유지 ✅

API 장애 시 (직접 호출 - 금지):
  - impression: 기록 안 됨
  - conversion: 기록됨 ❌
  - 통계 오염! ❌

    FunnelEventTracker¶

    순수 퍼널 이벤트를 비동기로 추적하는 서비스입니다.

    @Service
class ProductService(
    private val funnelEventTracker: FunnelEventTracker
) {
    fun viewProduct(userId: String, productId: Long) {
        // 퍼널 이벤트 추적 (비동기)
        funnelEventTracker.trackEvent(
            userId = userId,
            eventName = "view_product",
            funnelKey = "purchase_flow",
            metadata = mapOf("productId" to productId)
        )

        // 비즈니스 로직
        return productRepository.findById(productId)
    }
}

    메서드: - trackEvent(userId, eventName, sessionId?, funnelKey?, metadata?): 퍼널 이벤트 추적 - trackEventSafe(...): 예외를 무시하고 안전하게 추적

    특징: - ✅ Kotlin Coroutines 기반 비동기 저장 - ✅ 메인 로직에 영향 없음 (논블로킹) - ✅ ThreadPoolTaskExecutor로 성능 최적화 - ✅ Graceful Shutdown 지원 (잔여 이벤트 저장)

    PrismContext¶

    현재 요청 컨텍스트에서 실험 정보를 조회합니다.

    // 할당된 변형 조회
val variant = PrismContext.getCurrentVariant()

// 실제 할당 여부 확인 (API 장애 시 false)
val wasAssigned = PrismContext.wasActuallyAssigned()

    Examples Shop API¶

    prism-examples 모듈에서 제공하는 E-commerce 퍼널 예제 API입니다.

    1. 상품 조회 (실험 참가)¶

    GET /examples/shop/products/{id}¶

    상품 조회 시 buy_button_color 실험에 자동 참가합니다.

    파라미터:

    이름 타입 필수 설명
    id Long (path) ✅ 상품 ID
    userId String (query) ✅ 사용자 ID

    요청: 

    curl "http://localhost:8090/examples/shop/products/1?userId=user123"

    2. 장바구니 담기 (ADD_TO_CART 전환)¶

    POST /examples/shop/cart/add¶

    장바구니에 상품을 담고 ADD_TO_CART 전환 이벤트를 기록합니다.

    파라미터:

    이름 타입 필수 기본값 설명
    userId String ✅ - 사용자 ID
    productId Long ✅ - 상품 ID
    quantity Int ❌ 1 수량

    요청: 

    curl -X POST "http://localhost:8090/examples/shop/cart/add?userId=user123&productId=1&quantity=2"

    응답: 

    {
  "message": "Added to cart",
  "userId": "user123",
  "itemCount": 2
}

    3. 결제 (PURCHASE 전환)¶

    POST /examples/shop/checkout¶

    결제를 완료하고 PURCHASE 전환 이벤트를 기록합니다.

    파라미터:

    이름 위치 타입 필수 설명
    userId query String ✅ 사용자 ID
    cartItems body Array ✅ 장바구니 항목

    요청: 

    curl -X POST "http://localhost:8090/examples/shop/checkout?userId=user123" \
  -H "Content-Type: application/json" \
  -d '{
    "cartItems": [
      {"productId": 1, "quantity": 2},
      {"productId": 2, "quantity": 1}
    ]
  }'

    응답: 

    {
  "message": "Purchase completed",
  "userId": "user123",
  "value": 135000
}

    4. 주문 완료 (어노테이션 기반 전환 추적)¶

    POST /examples/shop/order/complete¶

    @PrismTrackConversion 어노테이션을 사용한 전환 추적 예제입니다.

    파라미터:

    이름 타입 필수 설명
    userId String ✅ 사용자 ID
    orderId String ✅ 주문 ID

    요청: 

    curl -X POST "http://localhost:8090/examples/shop/order/complete?userId=user123&orderId=ORD-001"

    응답: 

    Order ORD-001 completed for user user123

    에러 코드¶

    코드 HTTP 설명
    SUCCESS 200 성공
    EXPERIMENT_NOT_FOUND 200 실험을 찾을 수 없음 (variant=null 반환)
    INVALID_REQUEST 400 잘못된 요청
    INTERNAL_ERROR 500 서버 내부 오류
