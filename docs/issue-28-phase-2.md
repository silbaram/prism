# #28 Phase 2 — 실험 결과 신뢰성

Phase 1 위에 노출 중복 제거, SRM 검사, 그룹 간 검정, 설정 잠금과 변경 이력을 추가합니다.

## 실제 노출과 멱등성

`evaluate()`는 화면 준비용 순수 평가입니다. 사용자가 실제 경험을 보는 시점에 `recordExposure(result)`를 호출하세요. `assign()`은 실제 경험을 제공하는 시점에 평가와 노출 등록을 함께 수행하는 편의 API입니다. 노출 전에 호출하면 참여자를 과다 집계할 수 있으므로, 화면 준비·미리 불러오기에는 `evaluate()`를 사용합니다. 어노테이션과 Strategy도 실제 경험을 제공하는 경로에서 사용하세요.

LOCAL SDK는 **PrismClient 인스턴스 수명 동안 사용자×실험의 동일 변형 노출을 한 번만 큐에 넣습니다.** 애플리케이션에서 client를 공유하면 프로세스 수명 동안 적용됩니다. 동시 호출, ACK 이후, 조회 캐시 TTL·퇴출, 다른 실험 때문에 전체 설정 버전이 바뀌는 경우에도 원래 노출 ID·버전을 재사용합니다. 평가 자체는 매번 최신 설정으로 실행합니다.

- 중복 호출은 성공하며 `assign()` 결과에는 실제로 기록한 노출의 ID·버전이 들어갑니다. `evaluate()`는 현재 평가 버전을 반환합니다.
- 큐 등록에 실패한 노출은 중복 제거 목록에 넣지 않습니다. 서버에서 영구 거부한 노출은 목록에서 제거하여 다음 실제 노출을 다시 등록할 수 있습니다.
- 구버전 Admin이나 DB 직접 변경 등으로 같은 사용자가 다른 변형에 배정되면 새 노출을 기록합니다. 이를 이전 변형에 귀속시키지 않으며 Admin의 변형 간 중복 노출 검사로 검정이 차단됩니다.
- 중복 제거 목록은 기본 **100,000 사용자×실험**, `PrismClientOptions.exposureDedupCapacity` 또는 `prism.client.exposure-dedup-capacity`로 조정합니다. TTL·자동 퇴출은 없습니다. 한도에 도달하면 새 사용자×실험의 `assign()`은 실패 결과, `recordExposure()`는 false를 반환하고 로그를 남깁니다. 이미 등록한 조합과 전환 전송은 계속 동작합니다. 예상 프로세스 수명과 사용자 수에 맞춰 설정하세요.
- 목록은 메모리에만 있습니다. 서로 다른 client·프로세스 또는 재시작 사이의 중복 노출은 발생할 수 있지만 DB 지표는 계속 `COUNT(DISTINCT user_id)`로 집계합니다. 이벤트 큐·종료 flush의 유실 정책은 Phase 1과 같습니다.

전환 저장 멱등성은 Phase 1의 `event_id` 유니크 인덱스와 전역 receipt를 재사용합니다. **같은 이벤트의 재전송만 제거**하며, 별도 `track()` 호출은 서로 다른 이벤트입니다. 반복 구매 등 실제 여러 행동을 삭제하지 않습니다. CVR 분자는 목표 이벤트의 고유 사용자 수입니다. `(user, experiment, eventName)` 저장 유니크 제약은 추가하지 않습니다.

## SRM

실험 상세 화면에서 현재 잠긴 변형 가중치와 변형별 고유 노출 사용자 수를 비교합니다. Pearson 카이제곱 적합도 검정, 자유도는 양수 가중치 변형 수 − 1입니다. **p < 0.0005**를 경고 기준으로 사용합니다.

| 상태 | 의미 |
|---|---|
| PASS | 현재 표본에서 SRM 미감지. 데이터 품질 전체를 보증하지 않음 |
| MISMATCH | 기대 비율과 관측 비율이 달라 원인 조사 필요 |
| INSUFFICIENT_DATA | 양수 가중치 변형이 2개 미만이거나 기대 사용자 수가 하나라도 5 미만 |
| INVALID_DATA | 잘못된 가중치, 미등록·0% 변형 노출, 동일 사용자의 여러 변형 노출 |

0% 변형은 관측도 0일 때만 검정에서 제외합니다. 여러 변형에 노출된 사용자는 변형별 사용자 수의 합과 전체 고유 사용자 수를 비교해 감지합니다. 반복 행만 있는 경우에는 경고하지 않습니다. 설정과 집계는 REPEATABLE_READ 트랜잭션에서 읽습니다.

근거: [NIST 카이제곱 적합도 검정과 최소 기대 빈도](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/chsqgood.htm), [Microsoft SRM 진단과 경고 기준](https://www.microsoft.com/en-us/research/articles/diagnosing-sample-ratio-mismatch-in-a-b-testing/).

## 그룹 간 통계 정책 변경

#27에서 제외했던 그룹 간 검정을 다음 범위로 도입합니다. 기존 Wilson 95% 구간과 자동 승자 미제공 정책은 유지합니다.

- SRM PASS이고 **ENDED 상태**인 실험에서 목표 전환/미전환 × 변형의 단일 전체 카이제곱 검정을 제공합니다. 귀무가설은 모든 변형의 전환율이 같다는 것입니다.
- 가중치가 있는 모든 변형에 표본이 있어야 하며, 각 변형의 기대 전환·미전환 사용자가 각각 5 이상이어야 합니다. 관측자가 0명인 필수 변형을 제외하고 검정하지 않습니다. 작은 표본·목표 미설정·SRM 실패에는 p 값을 제공하지 않습니다.
- 양수 가중치 변형이 k개이면 자유도 k−1입니다. 2개 변형에서는 pooled two-proportion z-test의 양측 p 값과 같습니다. 연속성 보정은 사용하지 않습니다.
- 유의수준 0.05의 단일 검정이며 개별 변형의 승리나 인과관계 확정을 뜻하지 않습니다. 다중 쌍별 비교나 승자 배지는 추가하지 않습니다.
- **사전에 수집 종료 시점과 전환 관측 기간을 정해야 합니다.** 결과를 보고 중단하는 선택적 종료, 반복 관측, 여러 실험 중 유의한 결과 선택에 대한 보정은 없습니다. ENDED 전환만으로 이 통계적 조건이 보장되지는 않습니다.
- 종료 이후 지연 이벤트도 수집하므로 결과는 갱신될 수 있습니다. 최종 데이터 동결·전환 윈도 자동 적용·sequential testing은 후속 범위입니다.

근거: [NIST 분할표 검정](https://www.itl.nist.gov/div898/handbook/prc/section4/prc45.htm), [NIST 두 비율 차이 검정](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/diffprci.htm). p 값은 Apache Commons Math의 정규화 불완전 감마 함수 Q로 계산해 작은 꼬리 확률의 뺄셈 오차를 피합니다.

## 설정 잠금과 변경 이력

실험이 DRAFT를 벗어나면 `configuration_locked`를 영구 설정합니다. 이미 노출 로그가 있는 DRAFT도 잠긴 실험으로 취급합니다.

- 잠기는 항목: 실험 키, 목표 이벤트, 변형 이름·순서·가중치, 타겟팅 규칙. 변형 순서도 해시 구간을 바꾸므로 보호합니다.
- 설명 수정, ACTIVE↔PAUSED, ENDED 전환은 허용합니다. 일시중지해도 설정 잠금은 유지됩니다. DRAFT 복귀와 ENDED 재시작은 금지합니다. 변경된 실험은 새 키로 만드세요.
- 기존 잘못된 설정이나 목표 미설정 실험도 설정을 그대로 둔 채 일시중지·종료할 수 있습니다. 재활성화는 유효한 설정이 필요합니다.
- 시작했거나 노출이 있는 실험은 삭제하지 않고 ENDED로 보존합니다. 사용하지 않은 DRAFT만 삭제 가능합니다.
- 수정·시작·일시중지·삭제는 실험 행의 쓰기 잠금을 잡습니다. 동시에 열린 이전 폼으로 설정 잠금을 우회할 수 없습니다. 설정이 같으면 변형 행을 재생성하지 않습니다.
- `experiment_changes`에 CREATE/UPDATE/START/PAUSE/DELETE, 변경 전·후 JSON, UTC 시각을 같은 트랜잭션으로 기록합니다. 여러 규칙을 합친 스냅샷이 개별 규칙의 TEXT 한도를 넘을 수 있어 감사 스냅샷은 LONGTEXT로 저장합니다. 실패·롤백·동일 값 저장에는 새 이력을 남기지 않습니다. Admin 상세에 최근 50건을 표시하며 이전 이력은 DB에 보존합니다.
- 삭제한 DRAFT의 이력도 DB에 남깁니다. 인증이 없는 현재 단계에서는 변경자 신원을 기록하지 않습니다. DB 직접 변경은 애플리케이션 감사 대상에 포함되지 않습니다.

## 배포

1. DB 백업 후 API/Admin 쓰기를 중지합니다.
2. 기존 설치는 029까지 적용한 뒤 [030_experiment_reliability.sql](../prism-infrastructure/src/main/resources/migrations/030_experiment_reliability.sql)을 **한 번** 실행합니다. 신규 설치는 최신 `schema.sql`을 사용합니다.
3. API/Admin을 함께 갱신합니다. 구버전 Admin은 새 잠금 규칙과 이력을 적용하지 않으므로 함께 운영하지 마세요.
4. SDK/스타터 소비자를 다시 빌드하고 인스턴스를 공유합니다. 중복 제거 한도를 트래픽에 맞게 설정합니다.

마이그레이션은 기존 비-DRAFT와 노출 로그가 있는 실험을 현재 설정으로 잠급니다. **과거 가중치·타겟팅 변경 내역은 복원되지 않습니다.** 기존 실험의 과거 배정 기준이 불명확하면 해당 누적 결과를 새 검정의 의사결정 근거로 사용하지 말고 새 실험을 시작하세요. 이력 수집은 배포 이후부터 시작합니다. JDBC UTC 옵션은 Phase 1과 동일합니다.

- 수치 회귀: 균등·비균등·3개 변형, 알려진 p 값, 극단적 SRM, 0% 변형, 표본 부족, 그룹 간 중복 노출, 전체 전환율 검정과 차단 조건.
- SDK: 동시 노출 등록, ACK·조회 캐시 퇴출·설정 갱신 후 중복 억제, 원래 노출 참조의 전환 귀속, 큐·중복 제거 한도, 거부 후 재등록.
- Admin HTTP/JPA: 시작→중지→종료 잠금, 이전 폼 수정과 동시 시작, 감사 트랜잭션 롤백·무변경·삭제 보존·HTML 이스케이프, 실제 SRM·검정 화면.
- 실제 MySQL: 신규 스키마와 027→028→029→030 마이그레이션을 UTC·KST JVM에서 실행하며 기존 데이터, 잠금 백필, 감사 시각의 실제 UTC 저장을 검증합니다.
- 전체 빌드와 POM/Gradle metadata 기반 독립 Java SDK 소비자 실행을 포함합니다.
