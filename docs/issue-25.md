# 이슈 #25 — 실험별 순서형 퍼널

실험 상세나 이벤트별 집계 화면에서 **순서형 퍼널 보기**를 선택한다. 분석할 이벤트를 한 줄에 하나씩 입력하고 조회 시작·종료 시각(UTC), 첫 단계 이후 전환 제한 시간(1–720시간)을 지정한다. 단계는 2–8개, 조회 기간은 최대 366일이다. 기본 입력 기간은 최근 30일, 제한 시간은 24시간이다. 조회는 읽기 전용이며 Admin과 Viewer 모두 사용할 수 있다.

예를 들어 다음 이벤트를 SDK의 기존 전환 추적으로 수집한 뒤 조회한다.

```text
add_to_cart
begin_checkout
purchase
```

이벤트 이름의 대소문자·공백을 구분하며 같은 이벤트를 여러 단계에 반복해서 지정하지 않는다. 선택하지 않은 이벤트가 중간에 발생해도 경로는 유지된다. 목표 이벤트 여부와 관계없이 노출 귀속이 유효한 선택 이벤트를 사용한다. 기존 목표 CVR과 이벤트별 사용자 수·발생 횟수 집계는 그대로 유지한다.

## 집계 계약

조회 시각은 1970년 이후, 종료는 현재 UTC 시각 이하여야 한다. 저장된 로그와 비교할 수 있는 마이크로초 단위까지만 입력을 허용한다.

- 조회 기간은 `[시작, 종료)`다. 기간 안의 **최초 1단계 이벤트**부터 사용자×변형당 한 번 분석한다. 기간 이전에 시작한 경로를 이어 붙이지 않는다.
- 다음 단계는 앞 단계보다 엄격히 늦은 저장 시각에 발생해야 하고, 최초 1단계 시각부터 제한 시간 **미만**이어야 한다. 단계 건너뛰기, 첫 단계 이전의 이벤트, 제한 시간과 정확히 같은 시각의 마지막 단계는 인정하지 않는다.
- 최초 1단계가 반복되어도 시작 시각과 제한 시간을 다시 설정하지 않는다. 중간 단계의 반복도 사용자를 추가하지 않는다. 수집 순서와 관계없이 저장된 발생 시각으로 정렬한다.
- DB의 저장 시각을 사용한다. 동일 시각의 서로 다른 단계는 선후를 확정할 수 없으므로 다음 단계로 진행시키지 않는다. 페이지 커서는 시각과 행 ID로 모든 행을 읽지만, 행 ID로 이벤트의 선후를 추론하지 않는다.
- 제한 시간이 조회 종료 시각까지 끝난 사용자만 단계별 사용자 수와 전환율에 포함한다. 아직 끝나지 않은 사용자는 이미 마지막 단계를 수행했더라도 **관측 중**으로 별도 표시한다. 성공한 사용자만 먼저 넣는 편향을 피하기 위한 기준이다.
- 이전 단계 대비 전환율은 `현재 단계 사용자 / 이전 단계 사용자`, 첫 단계 대비는 `현재 단계 사용자 / 첫 단계 사용자`다. 분모가 0이면 `—`로 표시한다. 첫 단계는 이전 단계 대비 값이 없다.
- 일반 CVR처럼 해당 실험·사용자·변형의 유효한 노출 귀속을 확인한다. 새 이벤트는 지정한 노출 참조를 사용하며, 참조 없는 과거 이벤트는 앞선 노출이 있을 때만 포함한다.
- 변형별 기술 통계다. 한 사용자가 복수 변형에 노출되면 각 변형에 포함될 수 있으며, 변형별 수를 더해 전체 고유 사용자 수로 해석하지 않는다. 승자·유의성·인과 효과를 선언하지 않는다.

이 결과는 조회 시점에 저장된 로그를 바탕으로 하며 확정된 분석 결과가 아니다. 늦게 수집된 이벤트로 최초 단계와 경로가 달라질 수 있다. SDK 호스트의 시계 오차도 이벤트 순서에 영향을 준다. 기존 고급 분석의 관측 확정·지연 허용·CUPED와는 별도 계약이다.

## 구현과 운영

`/admin/experiments/{id}/funnel`에서 GET으로 조회한다. 기존 이벤트 API·SDK·스키마를 변경하지 않으며 별도 마이그레이션이 필요하지 않다. `steps`, `from`, `until`, `windowHours`를 쿼리 매개변수로 전달한다. 첫 방문은 입력 화면만 보여 주고, 입력 후 조회할 때 분석한다.

동일한 읽기 트랜잭션에서 유효한 선택 이벤트를 사용자·변형·시각·ID 순으로 1,000행씩 keyset 조회한다. 한 사용자×변형의 진행 상태와 변형별 누적 카운터만 유지하여 전체 로그를 메모리에 보관하거나 임의 행 수로 표본을 자르지 않는다. 페이지 중간에 사용자 이력이 끊겨도 진행 상태를 유지한다. 조회 비용은 대상 이벤트 수와 DB 정렬 비용에 비례하므로 큰 실험에서는 기간을 좁히고 응답 시간·DB 부하를 관측한다.

이번 구현 범위는 순서형 퍼널이다. 전체 사용자 여정의 경로 검색·세션 분석·개별 타임라인은 포함하지 않는다. 이슈 #25 전체 완료 여부는 해당 후속 범위와 별도로 판단해야 한다.
