# prism-admin

Prism A/B 테스트 플랫폼의 실험 관리 Admin 서비스 (Spring Boot + Kotlin + Thymeleaf 서버 렌더링).

실험 생성·목표 이벤트·변형/가중치/타기팅 설정, 참여 비율·레이어·홀드아웃 관리, 실험 상세와 통계(CVR·Wilson 95% 신뢰구간·SRM·검정), 고급 분석(순차 검정·Bayesian·CUPED·세그먼트), 시뮬레이터 화면을 제공합니다. 인증(ADMIN/VIEWER 역할) 후 사용됩니다.

## 구조
- `src/main/kotlin/...` — 애플리케이션/컨트롤러/서비스/보안
- `src/main/resources/templates/` — Thymeleaf 템플릿
  - `layout/default.html` — 공통 레이아웃(`th:fragment="layout(content)"`, `content` 파라미터로 페이지 삽입)
  - `experiment/` — 목록/생성·수정 폼/상세/이벤트/고급 분석
  - `simulator/`, `population/`, `error/`(status·4xx·5xx)
- `src/main/resources/static/`
  - `css/prism.css` — **디자인 토큰 & 기반 스타일** (컴포넌트 스타일 추가의 단일 진입점)
  - `vendor/bootstrap/<버전>/dist/{css,js}/` — Bootstrap 벤더링 + `LICENSE`(MIT)

## 디자인 시스템 (prism.css)
- 원칙: 색·간격·라운드·그림자·모션은 **토큰 경유** — 값 교체로 톤 전체 변경, 토큰 이름/구조는 유지.
- 현재 토큰: 간격(`--prism-space-*`), 라운드(`--prism-radius-*`), 그림자, 모션, 색 재노출(`--prism-color-*` → 현재 Bootstrap 기본값 추종).
- 컴포넌트 스타일을 새로 넣을 때는 이 파일에 섹션 추가로 축적, ~700줄 접근 시 분할 검토.
- 레이아웃·폼·테이블·배지 등 구조 클래스는 Bootstrap 유지 — 템플릿에서 Bootstrap 클래스와 토큰을 조합.

## Bootstrap 벤더링
- 대상: `bootstrap@5.3.8` — `dist/css/bootstrap.min.css`, `dist/js/bootstrap.bundle.min.js` (템플릿 실사용 범위와 일치; 아이콘 미사용 — 이모지/텍스트 사용).
- 라이선스: MIT, `vendor/bootstrap/<버전>/LICENSE` 동봉. 외부 네트워크 요청 없음(전량 로컬 서빙).
- 갱신 절차: 새 5.3.x 확인 → `<새 버전>/`에 자산+LICENSE 추가 → 템플릿 링크 교체 → 레이아웃/폼/테이블/다크 회귀 확인 → 이전 버전 디렉터리 정리(롤백 가능하도록 직전 버전 1개 유지 권장).
- 테마: `color-scheme: light` 기본. 다크 모드 적용됨(4단계 1차, `[data-bs-theme]` 기반) — 시스템 설정 존중 + `localStorage` 수동 오버라이드, `<head>` 조기 적용 스크립트(깜빡임 방지), 내비게이션 🌗 토글. 색 값은 Bootstrap `[data-bs-theme=dark]` 변수 오버라이드를 경유하므로 커스텀 팔레트 교체는 토큰 값 변경만.

## 접근성 기준 (요약)
키보드 조작/포커스 가시성, 색만으로 의미 전달 금지(텍스트 병기), 상태 대비 확보, `prefers-reduced-motion` 존중, 표 수치 정렬 기준 명시, 빈 상태/잠금/에러 상태 설계.

## 차트 정책
현재는 표 기반. 시각화 필요 시 1순위 **인라인 SVG(토큰 자동 연동)**, 인터랙티브가 필요해지면 Chart.js 등 벤더링 + 라이선스 검토.

## 진행 로그
- **0단계 (2026-11-11)** — 디자인 기반: Bootstrap 5.3.8 리포 벤더링(CDN 제거), `static/css/prism.css` 토큰 레이어 신설, `layout/default.html` 로컬 자산/viewport/lang 반영, 본 문서 추가.
- **1단계 (2026-11-11)** — 공통 정비: 페이지 타이틀 위계/표기 일관성(이벤트 h2 통일·시뮬레이터 인라인 스타일 정리), 에러 화면 톤 통일. 주의: `error/4xx.html`·`5xx.html`은 Boot 기본 에러 페이지(정적 리소스 서빙 경로)라 레이아웃/Thymeleaf 미탑재 자체 완결 문서 + 로컬 CSS로 작성(테마 토글 스크립트 미포함 — 기본 라이트로 렌더), `error/status.html`만 레이아웃 탑재(ControllerAdvice 경유).
- **2단계 (2026-11-11)** — 핵심 화면 정비: 실험 목록(검색/필터 카드 헤더 추가, 테이블 컬럼 인라인 폭 제거), 실험 상세(설정 잠김 안내 배너 — `configurationLocked` 기존 필드 활용). 생성·수정 폼은 동적 JS/검증 로직 밀집 구간이라 마크업·클래스 유지(동작 불변 원칙).
- **2단계 보충 (2026-11-12)** — 생성·수정 폼 정비(동작 불변): 정적 라벨-입력 `for`/`id` 연결, `readonly` 잠금 단서(배경·커서). 동적 JS/검증 로직은 미접촉.
- **정비, 정적 (2026-11-12)** — 시뮬레이터 라벨 연결·인라인 `display` 제거·표 래퍼·토큰 감사(중복 0).
- **3단계 1/3 (2026-11-12)** — 데이터 화면: 변형별 CVR 요약 바(CSS, 장식 — 수치·구간은 표가 정본)를 실험 상세·고급 분석에 추가. 데이터 가용성 실측 결과 노출/전환은 변형별 누적 집계뿐이라 **시간 추이 차트는 백엔드 요건(별도 결정)**, 홈 요약 대시보드는 기능 결정 사항으로 보류(현재도 목록으로 리다이렉트).
- **3단계 2/3 (2026-11-12)** — 데이터 화면: 고급 분석에 세그먼트별·Bayesian 요약 바 추가(척도 캡션 명기: 확률 0–100% / CVR 10% 상한 / 미등록 별도 집단). 요약 바는 장식(`aria-hidden`), 수치·구간·차이는 표가 정본.
- **4단계 1차 (2026-11-12)** — 다크모드: `data-bs-theme` 시스템 존중+오버라이드, FOUC 방지 스크립트, 내비게이션 토글, `[data-bs-theme=dark]{color-scheme:dark}` 명시(소스 순서상 Bootstrap 다크 블록과 동등한 우선순위 확보).
- **4단계 마감, 정적 (2026-11-12)** — 시뮬레이터 라벨 연결, 정적 inline `display` → `d-*` 클래스(JS 토글 등가), 데이터 표 `.table-responsive` 래퍼(실험 7·참여 2), 토큰 감사: 중복 0·클래스 층 소비.
- **4단계 보충 (2026-11-12)** — 에러 화면 3종 `role="alert"` 통일(폼 기존 관행과 일치).
- **정비 (2026-11-12)** — 접근성: 5개 템플릿 표 `th` 41개 `scope="col"`; 테마: `body bg-light` 제거(테마 변수 추종), 폼 예시 박스 `prism-tinted-surface` 토큰 표면으로 교체(다크에서 밝은 배경 잔존 방지).

- **페이지별 문서 제목(1차 수준)**: 레이아웃 fragment `title` 파라미터화 — 레이아웃 + 호출부 8곳 수정, 렌더 검증 필요. 현재 전 뷰 `<title>Prism Admin</title>`. A2(`role=alert`)는 반영됨.

## 검증 체크리스트 (환경 되면 우선순위 순)

1. **템플릿 렌더 스모크(최우선)** — 기동 가능 환경에서 목록/상세/생성·수정 폼/이벤트/고급 분석/시뮬레이터/참여 관리/에러 화면 순회. 특히 3단계 신규 표현식·`th:style`, 폼 클래스 토글, 다크모드 속성, 에러 3종.
2. **다크모드 수동 확인** — 토글 → `localStorage` 지속(새로고침), 시스템 설정 존중 기본값, FOUC 없음, 배지·차트·강제 색상 모드에서 대비.
3. **접근성 패스** — 키보드 탭 순회·포커스 링, 확대(200%)/축소 텍스트에서 레이아웃, `prefers-reduced-motion` 동작.
4. **반응형** — 좁은 뷰포트에서 표 스크롤 래퍼·내비게이션 collapse 동작.

현재 상태: 정적 점검(문구·구조·클래스·중복)까지만 수행 — Admin 기동은 JPA/DB 필요, 브라우저 실측은 이 환경에서 불가.

## 백로그 / 후속 결정

- **시간 추이 차트 — 백엔드 요건(이번 슬라이스 밖)**: 실측 결과 노출/전환은 변형별 누적 집계뿐, 시계열 버킷 없음. 신규 쿼리/기능 결정 후 착수.
- **홈(`/admin`) 요약 대시보드 — 기능 결정 필요**: 현재도 목록 리다이렉트 유지(권장: 결정 전 신설 안 함). 원하면 목록 상단 요약 밴드부터.
- **다음 차트 후보**: 세그먼트별·Bayesian 요약 완료(3단계 2/3). 추가 시각화는 데이터·우선순위 결정 필요.
- **인터랙티브 차트**: 정적 바로 시작 유지. 툴팁/확대 등 필요해지면 Chart.js류 벤더링 + 라이선스 검토 트리거.
- **로그인 화면 테마**: 전용 로그인 템플릿 없음(Spring Security 기본 페이지로 추정 — 기동 검증 필요). 기본 페이지는 앱 레이아웃/정적 CSS 미경유라 이번 다크모드 범위 밖.
- **생성·수정 폼 동적 영역**(variants/targetingRules JS 생성 마크업): 서버 렌더 마크업과 클래스 일치 — 정돈 필요 시 별도 슬라이스(검증 JS 불변 원칙).
